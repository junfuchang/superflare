# Docker 兼容说明

SuperFlare 当前不推荐以 Docker 作为默认部署方式，原因不是不能运行，而是它会弱化一些宿主机感知能力，尤其是端口可见性。

## 不推荐作为默认方案的原因

- 本项目后续目标是 fnOS / 飞牛 NAS 应用封装
- 端口采集这类能力在容器内天然受隔离影响
- 默认 Docker 网络只能看到容器侧端口，不能代表宿主机真实运行面

## 什么时候还能用 Docker

如果你只是为了快速体验页面本身，Docker 仍然可以跑。

但如果你的目标是：

- 读取宿主机真实端口
- 做飞牛应用形态适配
- 做长期本地调试和宿主侧能力联动

那么应优先使用原生运行方式。

## 容器内读取宿主机端口的前提

只有在额外挂载宿主机 `/proc`，并显式设置 `FLARE_PORT_PROC_ROOT=/host/proc` 之类参数时，容器内才可能看到宿主机端口信息。默认 Docker 部署不具备这个能力。

## 当前建议

- 日常开发：原生运行
- NAS 集成：基于 `fnApp/` 做应用封装
- Docker：仅作兼容实验，不作为主线
